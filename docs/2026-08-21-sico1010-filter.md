# Sico1010-Schalter in der Statistik

**Datum:** 21.08.2026
**App-Version danach:** `1.1.0.0`

Zwei Checkboxen über der Zeitraum-Leiste im Statistik-Tab. Ergänzt
`2026-08-21-statistik-tab.md`.

---

## 1. Die beiden Schalter

| Checkbox | Voreinstellung | Wirkung |
|----------|----------------|---------|
| **Sico1010 einbeziehen** | an | Abgewählt fällt die Sico1010 komplett heraus |
| **Nur verkaufte Sico1010 (Beschreibung xxxx-yyyy)** | aus | Zählt nur Sico1010, deren Beschreibung ein Verkaufskennzeichen trägt |

Beide Einstellungen liegen im `localStorage` (`stats_include_sico1010`,
`stats_sico1010_sold_only`) und überleben einen Reload. Die zweite Checkbox ist ausgegraut,
solange die erste aus ist — ohne Sico1010 gibt es nichts zu filtern.

Die Voreinstellungen sind so gewählt, dass sich beim ersten Öffnen **nichts** gegenüber vorher
ändert: alles ist drin, nichts ist gefiltert. Der Filter muss bewusst eingeschaltet werden.

## 2. „Aus der gesamten Berechnung"

Wörtlich genommen: Beide Schalter wirken auf **alles**, nicht nur auf das Diagramm.

- Balkendiagramm und Legende
- Tabelle „Anlagen je Produkt und Zeitraum" inklusive Summenspalte
- Kennzahlkarten und die große Gesamtzahl
- Tabelle „Entwicklung" (alle Prozentwerte und die Basis)
- Spalten „Anlagen", „Anlagen in %", „Ø Preis je Anlage" und „Betrag ggü. Anlagen" in
  „Lizenzen in Euro"
- Hinweis „N Anlagen ohne gültiges Datum"

Technisch hängt das an einem einzigen `activeProducts`-Computed; jede Aggregation iteriert
darüber statt über die Produktliste. Die **Farben bleiben am Produkt** (`colorSlot`), es wird
also nichts umgefärbt, wenn die Sico1010 verschwindet.

## 3. Was als „verkauft" gilt

Beschreibung enthält ein Wort im Format **vier Zeichen, Bindestrich, vier Zeichen** —
zum Beispiel `ABCD-1234`. Eine Bezeichnung mit nur vier Zeichen (`ABCD`) ist ein Update einer
bestehenden Anlage und zählt nicht als Verkauf.

```ts
const SOLD_SICO1010_PATTERN = /^[^\s-]{4}-[^\s-]{4}$/;

function isSoldSico1010(row: SicoAnlage): boolean {
  return (row.description ?? '').split(/\s+/).some((word) => SOLD_SICO1010_PATTERN.test(word));
}
```

Geprüft wird **wortweise mit Anker**, nicht irgendwo im Text. Sonst würde `Update-2024` als
Verkauf durchgehen, weil darin `date-2024` steckt. Nachgerechnet:

| Beschreibung | gilt als verkauft |
|--------------|-------------------|
| `ABCD-1234` | ja |
| `1234-5678` | ja |
| `Anlage ABCD-1234 Halle 3` | ja |
| `abcd-1234` | ja |
| `ABCD` | nein (Update) |
| `ABC-1234` / `ABCD-123` | nein |
| `ABCDE-12345` | nein |
| `Update-2024` | nein |
| leer / kein Wert | nein |

`SOLD_SICO1010_PATTERN` ist die **einzige** Stelle, die das Format kennt. Wenn die echten
Beschreibungen enger sind (nur Ziffern, fester Präfix), reicht es, diese Konstante zu ändern.

### Kontrollzahl in der Oberfläche

Neben den Checkboxen steht dauerhaft „**N von M** Sico1010 haben eine Beschreibung im Format
xxxx-yyyy". Damit lässt sich die Regel sofort an den echten Daten prüfen, ohne sie einzuschalten
— wirkt die Zahl falsch, stimmt das Muster nicht.

## 4. Zusammenspiel mit „ohne gültiges Datum"

Die Zählung der undatierten Datensätze läuft über die **bereits gefilterten** Zeilen
(`consideredRows`). Sonst würden herausgefilterte Update-Einträge fälschlich als „Datum fehlt"
gemeldet. Ebenso zählt sie nur Produkte, die eingeschaltet sind.
